# 05 部署入门

这篇讲把一个服务放到 Linux 服务器上跑起来的最小套路。假设你有一台 Ubuntu 22.04
的服务器，有 sudo 权限，程序是个 Python 的 web 服务。

## 0. 先搞清楚要做什么

部署这件事拆开就三件：

1. 让程序在后台一直跑（进程管理）——用 systemd
2. 让外面能访问到（反向代理 + HTTPS）——用 nginx
3. 出问题能查（日志）——journalctl + 应用日志

## 1. 登录服务器

```bash
ssh user@1.2.3.4
```

第一次会问 yes/no，输 yes。之后配免密登录（可选但强烈建议）：

```bash
# 在本地执行
ssh-keygen -t ed25519 -C "my-laptop"
ssh-copy-id user@1.2.3.4
```

**坑**：`ssh-copy-id` 把公钥装到服务器后，记得在服务器的
`/etc/ssh/sshd_config` 里关掉密码登录：

```
PasswordAuthentication no
```

然后 `sudo systemctl restart sshd`。**改之前先另开一个窗口验证新连接能上去**，
不然改错了就把自己锁在外面了。这个操作我建议第一次做的时候找个有控制台的人
在旁边。

## 2. 放代码

```bash
sudo mkdir -p /srv/myapp
sudo chown $USER:$USER /srv/myapp
cd /srv/myapp
git clone https://github.com/you/myapp.git .
```

## 3. 跑起来（先手动试）

```bash
cd /srv/myapp
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m myapp
```

先手动跑通，确认没问题再去配 systemd。**手动都跑不起来，配 systemd 只会更难查。**

## 4. 用 systemd 管理进程

写一个 unit 文件 `/etc/systemd/system/myapp.service`：

```ini
[Unit]
Description=My App
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/srv/myapp
Environment="PATH=/srv/myapp/.venv/bin"
EnvironmentFile=/srv/myapp/.env
ExecStart=/srv/myapp/.venv/bin/python -m myapp
Restart=on-failure
RestartSec=5

# 安全加固：限制这个进程能干什么
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload       # 改完 unit 文件必须执行
sudo systemctl enable --now myapp  # 开机自启 + 立刻启动
sudo systemctl status myapp        # 看状态
```

**坑一**：`EnvironmentFile` 里不能有 `export`，也不能用引号包值。就是
`KEY=value` 一行一个。写成 `export KEY=value` 会启动失败，报
`Failed to load environment files`。

**坑二**：`User=www-data` 的话，`/srv/myapp` 和里面的文件得让 www-data 能读。
`sudo chown -R www-data:www-data /srv/myapp`。不然报 `Permission denied`
但你用自己账号手动跑又没问题，很迷惑。

**坑三**：改了 unit 文件不 `daemon-reload`，systemd 还用旧的，你会觉得
"我明明改了怎么没生效"。

## 5. 看日志

systemd 会把程序打到 stdout/stderr 的东西收走：

```bash
journalctl -u myapp -f              # 实时跟
journalctl -u myapp --since "10 min ago"
journalctl -u myapp -p err          # 只看错误
journalctl -u myapp -n 100          # 最后 100 行
```

如果你的程序自己写日志文件，记得配 logrotate，不然磁盘会被写满。这个坑很常见，
服务器跑几个月突然所有服务挂掉，一看磁盘 100%。

## 6. nginx 反向代理

程序监听 `127.0.0.1:8000`，nginx 对外 80/443，转发进来。

`/etc/nginx/sites-available/myapp`：

```nginx
server {
    listen 80;
    server_name myapp.example.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 长连接和流式响应需要这些
        proxy_read_timeout 300s;
        proxy_buffering off;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/myapp /etc/nginx/sites-enabled/
sudo nginx -t          # 先测试配置！这个命令能救命
sudo systemctl reload nginx
```

**`sudo nginx -t` 一定要跑。** 配置写错了 reload 会失败但服务继续用旧配置跑，
你以为更新了其实没有。更糟的是直接 `restart`，服务直接挂了。

## 7. HTTPS

用 certbot 自动申请 Let's Encrypt 证书：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d myapp.example.com
```

它会自动改 nginx 配置加 443 和证书路径，还会配好自动续期。省事。

**坑**：`proxy_set_header X-Forwarded-Proto $scheme;` 这行不写的话，你的
程序会以为所有请求都是 http，生成的重定向链接会是 http 的，然后浏览器报
"重定向次数过多"。我查这个查了半小时。

## 8. 更新部署

```bash
cd /srv/myapp
git pull
source .venv/bin/activate && pip install -r requirements.txt
sudo systemctl restart myapp
```

正经项目应该做成脚本，甚至用 CI 自动跑。但小项目手动就够了，别过度工程。
