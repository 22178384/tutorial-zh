# 00 前言

## 这套东西是怎么来的

前两年我带过三个实习生，每来一个我就要重新讲一遍环境怎么配。讲到第三个的时候我
决定写下来。写完之后我发现一个额外的好处：我自己有时候也记不清 `docker compose`
某个参数，翻一下比查文档快。

所以这不是什么正经教程，更像是"一个干活的同事在旁边跟你念叨"。我尽量说实话，
包括哪些地方我自己也经常搞错。

## 先说几条原则

**1. 命令要自己敲一遍。**

看别人敲命令你永远学不会。哪怕你复制粘贴，也看一眼每个参数是什么意思。我带过的人
里，凡是只看的，过两天全忘。

**2. 报错信息要读完。**

这是我最想强调的一点。新手看到一屏红色的字就慌了，直接截图发给我。其实报错信息
第一行往往就写清楚了。比如：

```
ModuleNotFoundError: No module named 'requests'
```

这不就是没装 requests 吗。你读完自己就解决了。真的，先读完再问人。

**3. 不确定的命令，先 `--help`。**

```bash
docker run --help
git commit --help
```

比搜索引擎快。

## 一个我付过代价的教训

刚工作那会儿我在一台测试服务器上执行清理临时文件，写的是：

```bash
rm -rf /tmp/app-cache/
```

结果手一抖，多打了一个空格，变成：

```bash
rm -rf /tmp/app-cache /
```

中间那个空格把命令拆成了两段，第二段是 `rm -rf /`。那个瞬间我脑子是空白的。
幸好当时是测试机，而且没有 `sudo`，不然我就出名了。

所以：

- **`rm -rf` 后面不要跟变量**，除非你 `echo` 出来确认过
- **用 tab 补全，别手打路径**
- **危险命令先加 `echo` 看一遍**

```bash
# 先看会删什么
echo rm -rf "$TARGET_DIR"
# 确认没问题再执行
```

现在我自己写清理脚本，一律先 dry-run。

## 关于"我学不会命令行"

我听过太多次这句话。其实命令行的东西就那么几十个，常用的更少。你不需要背，
你需要的是知道"有这么个工具"，用的时候查一下。我到现在还经常 `man tar`。

真正难的不是记住命令，是理解为什么这么设计。这个只能靠多做。

## 环境说明

本套材料默认你在 Linux 或者 macOS 上。Windows 用户建议装 WSL2，然后把终端换成
Windows Terminal。纯 CMD 或者 PowerShell 我也能用，但和这套材料里的命令对不上，
你得自己转换。

Python 版本我用 3.10 和 3.11 测过。3.8 有些语法用不了（比如 `X | None` 的类型标注），
遇到会专门说。
